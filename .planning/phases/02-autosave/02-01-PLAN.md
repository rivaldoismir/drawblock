Port `Autosave` class apa adanya.

`useSaveQueue({ writer })`:
```ts
type Writer = (path: string, payload: string, expectedLastModified: number) => Promise<number>;
interface SaveQueue {
  status: SaveStatus; error: string | null;
  schedule(path: string, payload: string): void;         // debounce 1200 ms (catatan) / 1500 ms (gambar)
  flush(path?: string): Promise<void>;                   // tunggu antrean selesai
  flushAll(): Promise<void>;
  markLoaded(path: string, lastModified: number): void;  // baseline konflik
  hasPending(): boolean;
}
```
Aturan:
- `chains: Map<string, Promise<void>>` — tiap path punya rantai sendiri, path berbeda paralel.
- Versi perubahan per path: `versions: Map<string, number>`; saat save selesai, hanya set status `saved` jika versi tidak berubah; jika berubah, jadwalkan save berikutnya.
- `lastModified` terakhir per path (dari `markLoaded`/hasil write). Sebelum menulis, baca `file.lastModified`; jika berbeda dari yang diharapkan → panggil `onConflict(path)` dan JANGAN menulis.
- `payload` disimpan di `Map` (bukan closure lama) agar save selalu membaca isi terbaru.
- `flush()` menunggu rantai path itu; `flushAll()` menunggu semua.

Tes Vitest dengan writer palsu: (a) dua schedule cepat hanya menulis sekali; (b) perubahan saat write berlangsung memicu write kedua dan status tetap dirty sampai selesai; (c) dua path menulis paralel tanpa saling menunggu; (d) `lastModified` berubah → writer tidak dipanggil, konflik terpicu.
  </action>
